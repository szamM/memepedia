
# Backend авторизации Memepedia

## 1. Общая информация

- Проект: Memepedia
- Задача: MEM-14
- Спринт: Sprint 2
- Исполнитель по плану: Backend Developer
- Статус: Завершено в рамках учебной симуляции

## 2. Цель работы

Разработать Backend API для регистрации,
авторизации и управления сессиями пользователей.

## 3. Используемые технологии

- Node.js
- Express
- TypeScript
- PostgreSQL
- bcryptjs
- express-session
- connect-pg-simple
- Zod
- Helmet
- express-rate-limit

## 4. Реализованные маршруты

### GET /api/health

Проверяет работоспособность сервера
и соединения с базой данных.

Успешный ответ: 200 OK.

### POST /api/auth/register

Создаёт пользователя.

Функции:
- Валидация входных данных.
- Проверка уникальности email и username.
- Хеширование пароля.
- Сохранение пользователя в PostgreSQL.

Успешный ответ: 201 Created.

### POST /api/auth/login

Выполняет авторизацию пользователя.

Функции:
- Поиск пользователя по email.
- Проверка пароля.
- Создание серверной сессии.
- Установка сессионной cookie.

Успешный ответ: 200 OK.

### GET /api/auth/me

Возвращает данные пользователя,
связанного с текущей сессией.

Успешный ответ: 200 OK.

Без авторизации: 401 Unauthorized.

### POST /api/auth/logout

Завершает пользовательскую сессию.

Успешный ответ: 204 No Content.

## 5. Хранение данных

Пользователи хранятся в таблице users.

Поля:
- id
- username
- email
- password_hash
- created_at

Для предотвращения дублирования email
и username используются уникальные индексы.

Сессии сохраняются в PostgreSQL.

## 6. Меры безопасности

Реализованы:
- Хеширование паролей.
- Параметризованные SQL-запросы.
- Валидация данных через Zod.
- HttpOnly cookie.
- Обновление идентификатора сессии.
- Ограничение частоты запросов.
- Защитные HTTP-заголовки.
