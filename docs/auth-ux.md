
# UX-дизайн авторизации Memepedia

## 1. Общая информация

- Проект: Memepedia
- Спринт: Sprint 2 — MVP Development
- Задача: MEM-12
- Исполнитель: UX Designer
- Документ: Authentication UX Specification
- Статус: Согласован в рамках учебной симуляции

## 2. Цель проектирования

Разработать пользовательские интерфейсы
регистрации и авторизации Memepedia.

Интерфейсы должны быть:
- Понятными для пользователей.
- Визуально согласованными с UI-kit.
- Адаптивными.
- Доступными для управления с клавиатуры.
- Подготовленными для реализации на React.

## 3. Экран авторизации

### 3.1. Состав элементов

Экран должен содержать:

1. Логотип Memepedia.
2. Заголовок "Вход в аккаунт".
3. Поле Email.
4. Поле Пароль.
5. Кнопку "Войти".
6. Ссылку на страницу регистрации.
7. Область для сообщений об ошибках.

### 3.2. Пользовательский сценарий

1. Пользователь открывает страницу входа.
2. Вводит email.
3. Вводит пароль.
4. Нажимает "Войти".
5. Приложение отправляет запрос к API.
6. При успехе пользователь авторизуется.
7. При ошибке отображается сообщение.

Примечание:
В HTML-прототипе запросы API не выполняются.
Их реализация запланирована в MEM-13 и MEM-14.

## 4. Экран регистрации

### 4.1. Состав элементов

Экран должен содержать:

1. Логотип Memepedia.
2. Заголовок "Создать аккаунт".
3. Поле Имя пользователя.
4. Поле Email.
5. Поле Пароль.
6. Поле Подтверждение пароля.
7. Кнопку "Зарегистрироваться".
8. Ссылку на страницу входа.
9. Область для сообщений об ошибках.

### 4.2. Пользовательский сценарий

1. Пользователь открывает страницу регистрации.
2. Вводит имя пользователя.
3. Вводит email.
4. Придумывает пароль.
5. Повторно вводит пароль.
6. Нажимает "Зарегистрироваться".
7. Приложение проверяет данные.
8. При успехе создаётся учётная запись.
9. При ошибке отображается сообщение.

## 5. Требования к полям

### Email

- Обязательное поле.
- Формат email.
- Понятная подпись.
- Возможность отображения ошибки.

### Пароль

- Обязательное поле.
- Минимальная длина: 8 символов.
- Скрытый ввод.
- Возможность отображения ошибки.

### Имя пользователя

- Обязательное поле.
- Однострочный ввод.
- Проверка уникальности на сервере.

### Подтверждение пароля

- Обязательное поле.
- Значение должно совпадать с паролем.
- Ошибка должна быть понятна пользователю.

## 6. Визуальный стиль

Используется UI-kit проекта Memepedia.

Основные цвета:

- Primary: #6366F1
- Primary Hover: #4F46E5
- Background: #F8FAFC
- Surface: #FFFFFF
- Text: #0F172A
- Secondary Text: #64748B
- Border: #E2E8F0
- Error: #DC2626

Типографика:

- Основной шрифт: Arial, sans-serif.
- Заголовок: 28px, Bold.
- Основной текст: 16px.
- Подписи: 14px.

## 7. Состояния компонентов

### Поле ввода

- Default
- Focus
- Filled
- Error
- Disabled

### Кнопка

- Default
- Hover
- Focus
- Loading
- Disabled

### Сообщение об ошибке

- Появляется рядом с проблемным полем.
- Содержит конкретное описание ошибки.
- Не полагается только на красный цвет.

## 8. Адаптивность

Десктоп:
- Двухколоночная компоновка.
- Слева информационный блок.
- Справа форма.

Мобильные устройства:
- Одноколоночная компоновка.
- Форма занимает доступную ширину.
- Поля удобно использовать с телефона.

## 9. Доступность

- Все поля имеют label.
- У кнопок понятные названия.
- Есть видимый индикатор фокуса.
- Сохраняется логический порядок элементов.
- Формы доступны для навигации клавиатурой.

## 10. Критерии приёмки

- Подготовлен прототип страницы входа.
- Подготовлен прототип регистрации.
- Для страниц используются общие стили.
- Между страницами работают ссылки.
- Интерфейсы адаптируются к ширине экрана.
- Компоненты соответствуют UI-kit.
- Подготовлена документация.
